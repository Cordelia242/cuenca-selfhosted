# Cómo participar

Este proyecto se ofrece sin soporte y sin SLA (ningún compromiso de tiempos de respuesta ni de corrección): los issues se
leen y se responden cuando se puede.

Los issues con errores y las propuestas de mejora son bienvenidos. Usa las plantillas al
[abrir un issue](https://github.com/Cordelia242/cuenca-selfhosted/issues/new/choose).

## Pull requests

Por ahora no aceptamos pull requests. El código se desarrolla en un repositorio privado y aquí solo se publica compilado: el
paquete de instalación y la imagen del gateway. Un cambio propuesto como pull request no se podría integrar tal cual, así que
descríbelo en un issue de propuesta.

## Cómo escribir un buen issue

- Busca antes si ya existe un issue sobre lo mismo.
- Un issue por problema o propuesta.
- Indica la versión del paquete y tu sistema operativo.
- Para un error: los pasos exactos para reproducirlo, qué esperabas y qué pasó, y la salida de `./diagnostico.sh`. El informe
  oculta contraseñas y tokens, pero revísalo antes de pegarlo.
- Para una propuesta: qué problema resuelve y para quién, antes que cómo implementarla.
- Nunca pegues tokens, frases de paso, el contenido de `.env` ni datos financieros de personas.
- Las vulnerabilidades no van en issues: sigue [SECURITY.md](SECURITY.md).
